## Summary

- Fixed #833: `LlmExeError` set `cause` at runtime via `Object.defineProperty` but never declared it on the class, and `Error.cause` is ES2022 while `tsconfig.json` targets `es2021` — so `err.cause` failed to typecheck on a documented public option.
- Declared it as `declare readonly cause?: unknown`, matching how `name` / `isLlmExeError` are handled. `declare` emits no class field, so it cannot conflict with the `defineProperty` assignment; `unknown` matches the ES2022 `Error.cause` signature without claiming the cause is always an `Error`. Type-only, no runtime change, non-breaking.
- Added 5 cases to `LlmExeError.test.ts`: readable without a cast, `undefined`/not an own property when absent, non-`Error` cause preserved, still non-enumerable, and declared `cause` consistent with the serialized `cause` from `toJSON()`.
- Dropped the casts that existed only to read `cause` off an `LlmExeError` across 7 files, including `getErrorMetadata.ts` where `isLlmExeError()` already narrows. These double as the regression check — the direct `.cause` reads fail `tsc` without the fix.
- Verified: `npm test` 206 suites / 3353 tests passing, `npm run typecheck` clean, no new lint errors.
