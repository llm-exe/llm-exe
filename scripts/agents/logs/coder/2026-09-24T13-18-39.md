## Summary

- Fixed issue #813: `BaseExecutor.on()` / `.once()` / `.off()` / `removeHook()` accepted `ListenerFunction` (`(...args: any[]) => void`), so a hook's `executionMetadata` parameter was `any` — no inference on `input`, `output`, `handlerInput`, `handlerOutput`, and typos compiled silently.
- Both registration paths now share `ExecutorHookFunction<I, O, R, HI>`, matching what the `hooks` option already threaded through `CoreExecutorHookInput`. The `once()` self-removing wrapper is typed the same way.
- Types-only change; runtime behavior untouched. `ListenerFunction` stays exported and still types the internal hook-array storage, so nothing public was removed.
- Added a `hook registration type inference` block to `src/executor/type-inference.test.ts` — 4 cases covering metadata typing on `.on()` (incl. `handlerOutput.getResult().usage`), signature parity across `.on()`/`.once()`/`.off()`, contextual typing in an inline callback with `@ts-expect-error` on a typo'd property, and `hooks`-option vs `.on()` parity. These fail at `tsc` time without the fix.
