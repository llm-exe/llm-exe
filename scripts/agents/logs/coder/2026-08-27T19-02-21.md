## Summary

- Assigned issue #757 already had an open PR (#765) covering the type widening plus the Anthropic/Google/OpenAI mappers. Rather than duplicate it, took the **Ollama role guard** — item 2 of that PR's own "Still open on #757" list, and the only remaining piece that is independently landable on `development` (the check is runtime, so it needs none of #765's widened type).
- **Root cause**: `ollamaPromptSanitize` branches on `Array.isArray(_message.content)` with no role check, so an image block in a tool result produced `{ role: "function", content: "<text>", images: ["<base64>"] }`. Ollama's native `/api/chat` only honours `images` on `user` messages, so the image was silently dropped — the model answered as if it were never sent. Ollama does not share the OpenAI callback, so it did not inherit the typed throw #765 added for the OpenAI-compatible configs.
- **Fix**: throw `LlmExeError` with code `prompt.invalid_messages` when an `image_url` block appears on a `function`-role message, matching the resolution-message shape the file already uses for its remote-URL rejection. Narrowed to the silently-wrong path only — text-only block arrays on tool results still join to a string, and images on user messages are untouched.
- **Verified**: mutation-checked — stashing the source change fails exactly the one new image-on-tool-result test and nothing else. Full suite 199 suites / 3079 tests pass, `npm run typecheck` clean, no lint errors in the changed files (the 131 lint problems reported are pre-existing repo-wide and untouched by this change).
- Chose files with **zero overlap with PR #765**, so the two can land in either order without conflict — in particular did not touch `promptSanitizeContract.test.ts`, which #765 modifies.
