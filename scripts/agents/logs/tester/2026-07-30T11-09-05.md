## Summary
- Line coverage is already saturated (99.84% stmts / 99.28% branches / 100% lines, 2669 tests before this run), so per the prior run's recommendation I focused on **behavioral/regression** tests rather than chasing coverage numbers.
- Added `src/llm/config/promptSanitizeContract.test.ts` — a registry-driven cross-provider prompt contract. One table of canonical llm-exe message fixtures is run against **every** provider in `configs`, and each provider's native request body is asserted. This locks in the provider-agnostic promise from CLAUDE.md at the seam where it's actually enforced.
- Two things make it a contract rather than a restatement of the per-provider unit tests:
  1. **Driven by `configs`.** `PROVIDER_CONTRACTS` has one row per registered provider, and a coverage test compares the registry against the table — a new or renamed provider fails until someone writes down what it does with the fixtures.
  2. **Runs the real `mapBody` path**, not the sanitize callbacks in isolation. That covers wiring the per-provider tests can't reach: the body key (`messages` / `contents` / `prompt`), Bedrock's `allowImageUrlSources: false`, system hoisting to `system` / `system_instruction`, and consecutive-role merging (google's `functionResponse` merging into the preceding user turn). Every shorthand of a provider is asserted, so a shorthand rewired to a different sanitizer fails with its config key in the diff.
- Providers covered: `openai`, `xai`, `deepseek`, `openai.chat-mock` (verbatim passthrough), `anthropic`, `amazon:anthropic`, `amazon:meta`, `google`, `ollama`. Ollama and Bedrock/Llama had no cross-provider coverage before.
- Fixtures: plain text, leading system message, assistant turn, base64 `image_url` blocks, remote https images (incl. the Bedrock and Gemini rejections), assistant tool calls, and tool results.
- Also asserts the sanitizers do not mutate the caller's messages — including on the throwing fixtures, so a provider can't leave the caller's array half-transformed on the error path.
- **Falsifiability was verified, not assumed.** Removing `{ ..._message }` from the openai/anthropic/google/ollama sanitizers fails 10 mutation tests; removing the `xai.chat` row fails the coverage test; pointing `xaiChatV1`'s prompt transform at `googleGeminiPromptSanitize` fails 7 shape tests.
- No source changes. 199 tests in the new file. Full suite: 195 suites / 2868 tests passing, `npm run typecheck` clean. `npm run lint` reports 130 pre-existing errors on this branch, none in the new file.

## Findings
- **Filed [#706](https://github.com/llm-exe/llm-exe/issues/706)** — `ollamaPromptSanitize` returns early for any message whose `content` isn't an array, so `function_call` and `role: "function"` are sent to ollama in llm-exe's internal shape. Ollama's `/api/chat` expects `tool_calls` and `role: "tool"`, so tool calling against an ollama backend is very likely broken. Every other provider converts this. The contract file records the current behavior with a comment marking it as unhandled, not as a guarantee — those two rows need updating when #706 is fixed. Not fixed here; this is a test-only PR.
- `amazon:meta` flattens messages to a single text prompt via the DialogueHistory partial and drops tool metadata entirely. Recorded in `metaExpectations` as current behavior, not a guarantee.
- Anthropic's mutation guard is unobservable through the public path — `anthropicPromptSanitize` shallow-copies each message before invoking the callback, so removing the callback's own copy doesn't fail anything. Left un-asserted rather than pinning something `mapBody` can't reach.
