## Summary
- Fixed #893 (non-breaking): `execute(input, { traceId })` now scopes the trace ID to one call. `BaseExecutor.execute` resolves it once and threads it into `snapshotContext` (the `ExecutionContext.traceId` and `executor` metadata) and `runHook` (the `executorMetadata` hooks receive). It takes precedence over `withTraceId()` and does not mutate the instance value. The LLM layer already prefers `context.traceId` (`requestWrapper.ts`), so provider calls and errors pick it up too.
- Added `traceId?: string` to `LlmExecutorExecuteOptions`, and `traceId?: string | null` to `ExecutorMetadata`. It was already there at runtime but missing from the type, so hooks couldn't read `meta.traceId` without casting.
- `runHook` and `snapshotContext` gained an optional trailing `traceId` param. Two existing tests that assert `runHook`'s exact arguments now expect the trailing `undefined`.
- New `src/executor/per-call-trace-id.test.ts` covers the issue's concurrent repro, precedence over `withTraceId`, `onError`, and ignoring empty/non-string values. 3 of the 4 tests fail without the fix. Full suite: 211 suites / 3462 tests pass, typecheck is clean, and the touched files lint clean.
