## Summary
- Fixed #933: `createParser("json", { match: "extract" })` now throws `parser.parse_failed` with `reason: "truncated_json"` when the input contains a cut-off JSON value. Before, it silently returned a complete object nested inside the cut-off one.
- Added `hasTruncatedJsonOpener` in `JsonParser.ts`. An unclosed `{` or `[` counts as truncated JSON only when it is followed by what looks like the start of JSON: `"` after `{`; a string, number, nested value or `true`/`false`/`null` after `[`; or the end of the input. Stray brackets in prose (`Start: { but then {"a":1}`) are still skipped, so the existing tests keep passing.
- All 5 repro cases from the issue now throw, including "complete object + truncated object". The check runs only after strict `JSON.parse` fails in extract mode. Exact mode is unchanged.
- Without the fix, 7 of the new tests fail. Full suite: 212 suites / 3605 tests pass, typecheck is clean, and `JsonParser.ts` lints clean.
