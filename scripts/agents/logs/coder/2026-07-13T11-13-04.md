## Summary
- Fixed #661: the Anthropic provider silently dropped `temperature`/`topP`/`topK`. Root cause — the Anthropic `Config` never declared these as `options`, so `stateFromOptions` `pick()`'d them out before the body was built, leaving the `mapBody` reject-list transforms to only ever see `undefined`.
- Declared `temperature`, `topP`, `topK` in the Anthropic config's `options` so they survive `stateFromOptions` and flow into `mapBody`, where the existing `MODELS_REJECTING_SAMPLING_PARAMS` / `isClaude4x` guards now actually run for real `useLlm(...)` callers.
- Added `claude-fable-5` to `MODELS_REJECTING_SAMPLING_PARAMS` — live testing (per the issue) confirms it 400s on raw `temperature`, and the guard now fires for real, so it needs the entry to avoid breaking fable-5 users.
- Added a public-path regression test (`stateFromOptions` + `mapBody`, mirroring how `llm.call` builds the body) so the mapBody-direct tests can no longer mask this class of regression; also a fable-5 mapBody-direct case. Updated the exact-match config snapshot test for the new options.
- Verified: `npm test` (2551 passed), `npm run typecheck` clean. Lint has pre-existing repo-wide errors unrelated to these files; the two changed source/test files lint clean.
